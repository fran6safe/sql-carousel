Lesson 01 · Subqueries
What Is a Subquery?
A query nested inside another query — the inner result becomes a filter, value, or table for the outer query.
🎯
WHERE Subquery
Filter rows based on a computed value from another query.
📋
FROM Subquery
Use a query result as a virtual table in your FROM clause.
🔢
SELECT Subquery
Return a single computed value as a column alongside other data.
💡 Key insight

SQL evaluates the inner query first, then passes the result to the outer query. Think of it as solving the inner problem before tackling the outer one.

Lesson 02 · CTEs
Common Table Expressions
— Named, Reusable Logic
A CTE is a named temporary result set defined with WITH ... AS ( ) that you can reference like a table.
WITH high_earners AS ( SELECT name, department, salary FROM employees WHERE salary > 70000 ), dept_count AS ( SELECT department, COUNT(*) AS Total FROM high_earners GROUP BY department ) SELECT * FROM dept_count ORDER BY Total DESC;
Result
Engineering → 3 high earners
Marketing → 1 high earner

Why CTEs? Chain logic step-by-step, reuse the same result multiple times, and make queries readable by humans — not just machines.

Lesson 02 · CTEs
Chaining CTEs — Avg Salary by Dept
First filter employees earning above 60,000, then compute the average salary per department from that filtered set.
WITH higher_employee AS ( SELECT name, department, salary FROM employees WHERE salary > 60000 ), dept_avg AS ( SELECT department, avg(salary) AS AVG_S FROM higher_employee ) SELECT department, AVG_S FROM dept_avg GROUP BY department;
departmentAVG_S
Engineering87,800

Only Engineering employees clear the 60,000 threshold in this dataset — giving an average of 87,800. The second CTE builds directly on the first.

Lesson 03 · Window Functions
Analyse Across Rows
Without Grouping Them
Window functions perform calculations across a set of rows related to the current row — without collapsing the result.
PARTITION BY Divides rows into groups (like GROUP BY, but keeps individual rows intact).
ORDER BY (in OVER) Controls the order within each partition — critical for ranking and lag/lead functions.
ROW_NUMBER / RANK / DENSE_RANK Assign positions within a partition. They differ in how they handle ties.
LAG / LEAD Access values from previous or next rows — ideal for period-over-period comparisons.
🏆 Window functions vs GROUP BY

GROUP BY collapses rows into one per group. Window functions keep every row and add a computed column alongside — you can do both in one query.

AVG Over Partition &
Row Number by Dept
Dept Average + Diff
SELECT name, department, salary, AVG(salary) OVER ( PARTITION BY department) AS dept_avg, salary - AVG(salary) OVER ( PARTITION BY department) AS diff_from_avg FROM employees;
Row Number by Dept
SELECT name, department, salary, ROW_NUMBER() OVER ( PARTITION BY department ORDER BY salary DESC) AS dept_rank FROM employees;

Lesson 03 · Window Functions
RANK, DENSE_RANK
& LAG Explained
-- Global salary ranking SELECT name, salary, RANK() OVER (ORDER BY salary DESC) AS rank_1, DENSE_RANK() OVER (ORDER BY salary DESC) AS rank_2 FROM employees;
namesalaryrank_1rank_2
Charlie120,00011
Eve95,00022
Alice85,00033
-- Compare to previous salary SELECT name, salary, RANK() OVER (ORDER BY salary DESC) AS rank, LAG(salary) OVER (ORDER BY salary DESC) AS prev_salary FROM employees;
namesalaryrankprev_salary
Charlie120,0001NULL
Eve95,0002120,000
Alice85,000395,000

RANK vs DENSE_RANK: Both give the same rank when there are no ties. With ties, RANK skips numbers (1, 1, 3…) while DENSE_RANK doesn't (1, 1, 2…). LAG pulls the value from the previous row — NULL for the first.

Lesson 04 · CASE Statements
Inline Conditional Logic
— CASE WHEN
CASE WHEN acts like an IF/ELSE inside SQL — evaluate conditions row-by-row and return a value for each outcome.
SELECT name, salary, CASE WHEN salary > 90000 THEN 'High' WHEN salary > 60000 THEN 'Medium' ELSE 'Low' END AS salary_band FROM employees;

Summary
Your SQL Cheat Sheet
4 concepts — when to use each one at a glance.
Subquery
Filter on a computed value from another query. Best for simple, one-off comparisons.
CTE
Name and reuse intermediate results. Best when logic has multiple steps or is reused.
Window Function
Rank, aggregate or compare across rows without collapsing them. Best for analytical output.
CASE Statement
Apply conditional labels or values row-by-row. Best for bucketing, flagging, or categorising.
